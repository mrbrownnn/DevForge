# Skill security reports

Generated by `devforge skill audit` against every entry in
[`registry/catalog.yaml`](../registry/catalog.yaml) at its pinned commit, on
2026-08-19. Each report records the commit, the content hash of the tree that was
actually fetched, the detected licence, the risk verdict with its reasoning, and
every finding with a file and line.

These are evidence, not endorsement. `registry/catalog.yaml` deliberately keeps
`content_hash` and `last_audited` null: a shipped hash goes stale silently, and the
hash that matters is the one computed at install time and written to your
`skills.lock`.

## Two calibration lessons, kept here because they matter

**Mention is not access.** The first run rated `ci-cd-and-automation` CRITICAL for a
table teaching `.env → NOT committed`. Flagging good hygiene advice as hostile is how
a scanner gets switched off. The credential rules are now split three ways:
an instruction to *read or send* credentials is CRITICAL, code pulling a secret from
the environment is HIGH, and a bare mention is MEDIUM.

**Scripts are not instructions.** `supply-chain-risk-auditor` genuinely reads the
`gh` CLI token — in a collector script, for API rate limits. Credential access in
*instructions* steers the agent and stays a refusal; the same pattern inside a
shipped script is capability, and those scripts are quarantined and never executed,
so it is HIGH and a human decides.

## Reproducing

```bash
devforge skill audit <name>          # fetches at the pin, writes a report, installs nothing
devforge skill audit <name> --json   # same, machine-readable
```

Reports are regenerated, not edited. A stale report is a bug; delete it and re-audit.
